# Phase 5 — 用例评审

> 依赖：Phase 1（两种用例库）
> 本阶段相对独立，可在 Phase 3/4 之后随时开始。
> 本阶段完成后：可对 API 用例或功能用例发起评审流程，多人参与，追踪通过率。

---

## 核心流程

```
发起人 创建评审
  → 选择用例（来自 API 用例库 或 功能用例库）
  → 指定评审人（多人）+ 截止日期
  → 评审人逐条标记：通过 / 不通过 / 待修改 + 填写意见
  → 达到截止日期或所有人完成 → 评审结束
  → 查看评审通过率
```

## 后端

### 新增数据库模型

**文件：** `backend/app/models/case_review.py`

```python
class CaseReview(Base):
    __tablename__ = "case_reviews"

    id          = Column(Integer, primary_key=True)
    project_id  = Column(Integer, ForeignKey("projects.id", ondelete="CASCADE"))
    title       = Column(String(200), nullable=False)
    status      = Column(String(20), default="active")  # active/completed/expired
    deadline    = Column(Date, nullable=True)
    created_by  = Column(Integer, ForeignKey("users.id"))
    created_at  = Column(DateTime, default=datetime.utcnow)

    members = relationship("CaseReviewMember", back_populates="review", cascade="all, delete")
    items   = relationship("CaseReviewItem",   back_populates="review", cascade="all, delete")


class CaseReviewMember(Base):
    __tablename__ = "case_review_members"

    id        = Column(Integer, primary_key=True)
    review_id = Column(Integer, ForeignKey("case_reviews.id", ondelete="CASCADE"))
    user_id   = Column(Integer, ForeignKey("users.id"))
    status    = Column(String(20), default="pending")  # pending/completed

    review = relationship("CaseReview", back_populates="members")


class CaseReviewItem(Base):
    __tablename__ = "case_review_items"

    id        = Column(Integer, primary_key=True)
    review_id = Column(Integer, ForeignKey("case_reviews.id", ondelete="CASCADE"))
    case_type = Column(String(20), nullable=False)    # 'api' | 'functional'
    case_id   = Column(Integer, nullable=False)
    reviewer_id = Column(Integer, ForeignKey("users.id"), nullable=True)  # 哪个评审人的意见
    result    = Column(String(20), default="pending") # pending/approved/rejected/needs_change
    comment   = Column(Text, nullable=True)
    reviewed_at = Column(DateTime, nullable=True)

    review = relationship("CaseReview", back_populates="items")
```

> **设计说明：** `case_review_items` 中每条记录对应「一个评审人对一个用例的评审意见」。
> 即若有3个评审人、10个用例，则产生30条 items 记录。

### 新增 API 路由

**文件：** `backend/app/api/v1/case_reviews.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/projects/{id}/case-reviews` | 评审列表（含通过率统计） |
| POST | `/projects/{id}/case-reviews` | 创建评审（含用例列表+评审人） |
| GET | `/case-reviews/{review_id}` | 评审详情（含所有条目） |
| PUT | `/case-reviews/{review_id}` | 更新评审基本信息 |
| DELETE | `/case-reviews/{review_id}` | 删除评审 |
| PATCH | `/case-reviews/{review_id}/items/{item_id}` | 评审人提交单条用例评审意见 |
| POST | `/case-reviews/{review_id}/complete` | 完成评审（发起人操作） |

## 验收标准

- [ ] 可以创建评审，选择 API 或功能用例，指定多名评审人和截止日期
- [ ] 评审列表展示通过率、已评人数、状态
- [ ] 评审人进入详情可对每条用例标记通过/不通过/待修改，可填写意见
- [ ] 不同评审人的意见互相可见
- [ ] 发起人可手动将评审标记为「已完成」
- [ ] 超过截止日期未完成的评审自动变为「已过期」状态
