# 测试平台「双用例库」架构设计 — 总览

> 本文档是整体架构说明，具体实施细节见各阶段文件。

---

## 核心架构思路

在现有 API 自动化测试平台基础上，新增「功能测试用例库」，形成双轨并行架构。
测试计划、用例评审、测试报告等上层模块可同时引用两种用例来源。

```
用例来源层
  ├── API 测试用例库（/testcases）    ← 现有，改造：内嵌执行调试，下线独立 /testruns 页
  └── 功能测试用例库（/functional-cases） ← 新增：列表/脑图双视图 + .xmind 导入导出

上层模块
  ├── 测试计划（/test-plans）        ← 新增：编排两种用例的正式执行
  ├── 测试概览（/dashboard）         ← 改造：从空壳变为数据大盘
  ├── 测试报告（/reports）           ← 增强：支持按计划生成混合报告
  └── 用例评审（/case-reviews）      ← 新增：两种用例均可发起评审
```

---

## 执行入口对比

| 入口 | 场景 | 结果归档 |
|------|------|----------|
| API用例库页面内嵌调试 | 开发阶段临时调试单条接口 | 仅在用例详情内查看，不归档到计划 |
| 测试计划执行 | 正式测试轮次，批量执行一批用例 | 绑定到测试计划，纳入报告统计 |

## 最终页面导航结构

```
侧边栏
├── Dashboard（数据大盘）          [Phase 3]
├── 项目管理                       [已完成]
├── API 测试用例库                 [Phase 1 改造]
│     内含：用例CRUD + 内嵌执行调试 + 执行历史
├── 功能测试用例库                 [Phase 1 新增]
│     内含：列表视图 / 脑图视图 / .xmind 导入导出
├── 测试计划                       [Phase 2 新增]
│     内含：创建计划 + 选用例(双来源) + 执行 + 进度
├── 用例评审                       [Phase 5 新增]
└── 测试报告                       [Phase 4 增强]
      内含：按计划报告 + 历史执行记录
```
