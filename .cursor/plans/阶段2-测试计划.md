# Phase 2 — 测试计划

> 依赖：Phase 1 完成（需要 func_test_cases 数据）
> 本阶段完成后：可创建测试计划，编排 API + 功能两种用例，正式执行并追踪进度。

---

## 核心逻辑

测试计划是连接「用例库」与「正式执行」的枢纽：

```
创建测试计划
  → 从 API 用例库选入用例（case_type = 'api'）
  → 从功能用例库选入用例（case_type = 'functional'）
  → 执行：
      API 用例    → 触发 testruns 自动执行 → 结果自动写回
      功能用例    → 手动逐条标记结果（通过/失败/阻塞/跳过）
  → 进度实时追踪
  → 完成后生成测试报告（Phase 4）
```

class TestPlan(Base):
    __tablename__ = "test_plans"

    id          = Column(Integer, primary_key=True)
    project_id  = Column(Integer, ForeignKey("projects.id", ondelete="CASCADE"))
    name        = Column(String(200), nullable=False)

    status      = Column(String(20), default="draft")  # draft/active/completed/archived
    start_date  = Column(Date, nullable=True)
    end_date    = Column(Date, nullable=True)
    created_by  = Column(Integer, ForeignKey("users.id"), nullable=True)
    created_at  = Column(DateTime, default=datetime.utcnow)
    updated_at  = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

    items = relationship("TestPlanItem", back_populates="plan", cascade="all, delete")


class TestPlanItem(Base):
    __tablename__ = "test_plan_items"

    id          = Column(Integer, primary_key=True)
    plan_id     = Column(Integer, ForeignKey("test_plans.id", ondelete="CASCADE"))
    case_type   = Column(String(20), nullable=False)   # 'api' | 'functional'
    case_id     = Column(Integer, nullable=False)       # 对应各自用例表的 id
    status      = Column(String(20), default="pending") # pending/passed/failed/blocked/skipped
    executed_by = Column(Integer, ForeignKey("users.id"), nullable=True)
    executed_at = Column(DateTime, nullable=True)
    comment     = Column(Text, nullable=True)
    defect_ids  = Column(JSONB, default=[])             # 关联缺陷 ID 列表
    sort_order  = Column(Integer, default=0)
    created_at  = Column(DateTime, default=datetime.utcnow)

    plan = relationship("TestPlan", back_populates="items")

### 关键逻辑：执行 API 用例

```python
# POST /test-plans/{plan_id}/execute-api
def execute_api_cases(plan_id, environment_id, db):
    plan = get_plan(plan_id, db)
    api_items = [i for i in plan.items if i.case_type == 'api']
    case_ids = [i.case_id for i in api_items]

    # 复用现有 testruns 机制，传入 plan_id 做关联
    test_run = create_test_run(
        project_id=plan.project_id,
        case_ids=case_ids,
        environment_id=environment_id,
        plan_id=plan_id,   # ← 新增字段，关联到测试计划
        db=db
    )
    # Celery 执行完后，回调更新 test_plan_items.status
    return test_run
```

> **注意：** 需要在 `test_runs` 表新增 `plan_id` 字段（nullable），执行完成后
> 通过 Celery 回调将结果同步写回对应的 `test_plan_items.status`。
